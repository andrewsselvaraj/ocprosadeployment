# 4. Kubernetes and OpenShift

OpenShift **is** Kubernetes plus extras (Routes, BuildConfigs, ImageStreams, a web console, stricter
security defaults). Everything below works with `oc`; plain `kubectl` works for the non-OpenShift objects.

## 4.1 Objects used, and where they are

| Object | What it does | File |
|---|---|---|
| **Deployment** | Runs N identical pods, replaces them gradually on change | [base/*-service.yaml](../deploy/k8s/base) |
| **Pod** | One running instance (here: one container per pod) | created by the Deployment |
| **Service** | Stable DNS name + load balancing to ready pods (`http://question-service:8080`) | same files |
| **Route** (OpenShift) | Public HTTPS URL for a Service, TLS on the router | [base/api-gateway.yaml](../deploy/k8s/base/api-gateway.yaml) |
| **ConfigMap** | Non-secret settings as env vars | [base/app-config.yaml](../deploy/k8s/base/app-config.yaml) |
| **Secret** | Passwords, JWT key (base64, access-controlled, not in git) | generated by [overlays/dev](../deploy/k8s/overlays/dev/kustomization.yaml) |
| **StatefulSet + PVC** | MySQL with stable identity and a persistent EBS volume (dev) | [components/mysql](../deploy/k8s/components/mysql/mysql.yaml) |
| **NetworkPolicy** | Firewall rules between pods | [base/network-policies.yaml](../deploy/k8s/base/network-policies.yaml) |
| **HorizontalPodAutoscaler** | Adds/removes pods based on CPU | [overlays/prod/autoscaling.yaml](../deploy/k8s/overlays/prod/autoscaling.yaml) |
| **PodDisruptionBudget** | Keeps ≥ 1 pod up during node drains / cluster upgrades | same file |
| **ServiceMonitor** | Tells Prometheus to scrape `/actuator/prometheus` | [components/monitoring](../deploy/k8s/components/monitoring/service-monitor.yaml) |
| **ImageStream / BuildConfig** (OpenShift) | Builds images inside the cluster, tracks image versions | [openshift/builds.yaml](../deploy/openshift/builds.yaml) |

## 4.2 Anatomy of a service Deployment

Taking [identity-service.yaml](../deploy/k8s/base/identity-service.yaml) section by section:

**Configuration injection.** `envFrom: configMapRef m2its-config` loads all shared settings; `env` adds the
service-specific ones. `$(DB_HOST)` is expanded by Kubernetes from variables defined earlier, which gives a
per-service JDBC URL from shared parts:

```yaml
- name: DB_URL
  value: jdbc:mysql://$(DB_HOST):$(DB_PORT)/identity_db?$(DB_PARAMS)
- name: DB_PASSWORD
  valueFrom: { secretKeyRef: { name: identity-db, key: DB_PASSWORD } }
```

**Health probes** (Spring Boot Actuator provides the endpoints):

| Probe | Endpoint | Failing means | Kubernetes reaction |
|---|---|---|---|
| `startupProbe` | `/actuator/health/liveness` | still starting (up to 30 × 5 s) | wait; other probes paused |
| `livenessProbe` | `/actuator/health/liveness` | app is broken (deadlock…) | **restart** the container |
| `readinessProbe` | `/actuator/health/readiness` (includes DB) | can't serve right now | **stop sending traffic**, no restart |

Putting the DB check in *readiness* but not *liveness* is deliberate: a database outage should take pods
out of rotation, not restart them in a loop.

**Resources and the JVM:**

```yaml
resources:
  requests: { cpu: 100m, memory: 512Mi }   # what the scheduler reserves
  limits:   { memory: 768Mi }              # hard cap: exceeded → OOMKilled
```

- No CPU limit: CPU limits throttle the JVM during start-up (JIT, class loading) and slow everything; the
  request still guarantees a fair share.
- `JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=60.0` → heap ≈ 460 MB of the 768 MiB limit; the rest is
  metaspace, thread stacks, buffers.

**Zero-downtime rollouts:** `maxUnavailable: 0`, `maxSurge: 1` + readiness probe + `preStop: sleep 5` +
Spring `server.shutdown: graceful`. A new pod must be Ready before an old one is removed, and old pods finish
in-flight requests before exiting.

**Pod security:** `runAsNonRoot`, no privilege escalation, all Linux capabilities dropped, `RuntimeDefault`
seccomp. This satisfies OpenShift's default `restricted-v2` SCC without any special permissions.

## 4.3 Networking

```
Internet ──HTTPS──▶ OpenShift router ──▶ Service api-gateway ──▶ gateway pods
                                                   │
               ┌──────────────┬────────────────────┼──────────────┐
               ▼              ▼                    ▼              ▼
        identity-service academic-service  question-service ◀── exam-service
```

[NetworkPolicies](../deploy/k8s/base/network-policies.yaml) start from **deny all ingress** and allow only:
router → gateway, gateway → backends, exam → question, monitoring → all, backends → MySQL. So a compromised
gateway pod (the only one exposed to the internet) still cannot open a connection to MySQL.

## 4.4 Kustomize: one base, several environments

```
deploy/k8s/
├── base/                    what every environment has
├── components/
│   ├── mysql/               opt-in: in-cluster MySQL
│   └── monitoring/          opt-in: ServiceMonitor
└── overlays/
    ├── dev/                 namespace m2its-dev, 1 replica, MySQL component, internal-registry images,
    │                        secrets generated from local files, auto-redeploy after builds
    └── prod/                namespace m2its-prod, 2+ replicas, HPA + PDB, RDS endpoint, TLS to DB,
                             JSON logs, Swagger off, zone spreading, CI-built image tags
```

```powershell
oc kustomize deploy/k8s/overlays/dev          # render: inspect what would be applied
oc diff -k deploy/k8s/overlays/dev            # compare with the cluster
oc apply -k deploy/k8s/overlays/dev           # apply
```

Kustomize is built into `oc`/`kubectl`, so there's no extra tool and no templating language: overlays *patch*
plain YAML. (Helm is the common alternative when you need to publish reusable, parameterised charts.)

**Why PDBs only in prod:** with a single replica, `minAvailable: 1` makes a pod impossible to evict, so
node drains (and therefore ROSA upgrades) would hang.

## 4.5 Secrets

- **Dev:** [scripts/new-dev-secrets.ps1](../scripts/new-dev-secrets.ps1) writes random values to
  `deploy/k8s/overlays/dev/secrets/*.env` (git-ignored); Kustomize's `secretGenerator` turns them into Secrets.
- **Prod:** don't keep secrets in files. Recommended on ROSA: **External Secrets Operator** reading
  **AWS Secrets Manager** through an IAM role bound to a ServiceAccount (STS, no static AWS keys). See
  [06-devops-cicd.md](06-devops-cicd.md#64-secrets-management).

## 4.6 Everyday commands

| Task | Command |
|---|---|
| Switch project (namespace) | `oc project m2its-dev` |
| What is running? | `oc get pods,deploy,svc,route` |
| Why is a pod unhappy? | `oc describe pod <pod>` (see **Events** at the bottom) |
| Logs (follow, all pods of a deployment) | `oc logs -f deployment/exam-service` |
| Logs of the previous crashed container | `oc logs <pod> --previous` |
| Shell inside a pod | `oc rsh deployment/identity-service` |
| Call a service from your PC | `oc port-forward svc/question-service 8083:8080` → http://localhost:8083/swagger-ui.html |
| Restart pods (re-read secrets) | `oc rollout restart deployment/identity-service` |
| Roll back the last change | `oc rollout undo deployment/identity-service` |
| Scale manually | `oc scale deployment/exam-service --replicas=3` |
| Events, newest last | `oc get events --sort-by=.lastTimestamp` |
| Resource usage | `oc adm top pods` |
